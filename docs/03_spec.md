# 要件定義書

> 元になった顧客仮説: `docs/01_customer.md`（明光義塾三鷹校・田中教室長）
> 🔮 が付いた行は、まだ確かめていない仮説にもとづく決めごとです。

## 1. このツールが解くこと

**今日返信すべき問い合わせが、開いた瞬間に、待たせている順で分かる。**（結果として、月2〜3件の返信漏れが減る）

## 2. 使う人と、使う場面

- **使う人**: 明光義塾三鷹校の田中教室長（本人が1人で入力・操作する。他のスタッフとの共有はしない）
- **いつ開くか**: 🔮 朝、教室に着いてすぐ。および、問い合わせを受けた直後に1件入れるとき
  （→ 確かめ方: 「朝、教室に来て最初にやることは何ですか？」）
- **開いて最初にしたいこと**: **まだ返信していない人が、何人、どれくらい待たされているか**を見る

## 3. 画面（テンプレートの3画面をそのまま使う）

画面は **一覧 / 新規登録 / 設定** の3つ。左メニューで切り替える。ルーティングは増やさない。

**「一覧」に、上から順にこれが表示される:**

1. **数字が3つ**（未返信 / 3日以上待たせている / 全件）── 未返信の数がいちばん大きく出る
2. **検索欄と絞り込み**（未返信 ⇄ 返信済み ⇄ 全部。**最初は「未返信」が選ばれた状態**で開く）
3. **問い合わせの一覧**（**問い合わせ日が古い順＝待たせている順**。各行に 保護者名・流入元・問い合わせ日と経過日数・メモ・「返信済みにする」ボタン）

- **新規登録**: 4項目（保護者名／流入元／問い合わせ日／メモ）を入れて保存 → 一覧に「未返信」で追加される
- **設定**: 画面の表示名の変更と、データの初期化（全消し）だけ

> ⛔ この画面に、キャッチコピー・課題の説明・「無料で始める」等のCTA・営業文は出さない。
> ⛔ この文書の「6. やらないこと」や `docs/01_customer.md` の 🔮 仮説・出口の話は、画面に出さない（社内メモ）。

## 4. データ項目

**1種類のデータ =「体験授業の問い合わせ 1件」**。項目は5つ。

| 項目 | 型 | 必須 | 例 |
|---|---|---|---|
| 保護者名（生徒名） | 文字 | ✔ | 見本：Aさん（中2） |
| 流入元 | 選択肢（LINE / 電話 / HP / その他） | ✔ | LINE |
| 問い合わせ日 | 日付（YYYY-MM-DD） | ✔ | 2026-08-19 |
| メモ | 文字（自由入力・空でよい） | | 週2希望・英語と数学／18時以降に折り返し |
| 返信済みか | はい / いいえ | ✔ | いいえ（新規登録すると必ず「いいえ」で入る） |

- 🔮 **流入元をこの4つにした根拠**: 2行目の「LINEと電話とHP」そのまま＋取りこぼし用に「その他」。
  → 確かめ方: 「問い合わせって、LINE・電話・HP以外の入り口もありますか？」
- 🔮 **問い合わせ日を持つ根拠**: 「返信漏れが月2〜3件」＝**日数が経ったものが埋もれている**のが原因と見たため。この項目が「待たせている順」と「3日以上」の判定を作る。

## 5. 操作（3つまで）

| # | 操作 | 何が起きるか |
|---|---|---|
| 1 | **新規登録する** | 4項目を入力して保存 → 一覧の先頭ではなく**日付順の正しい位置**に「未返信」で入る。上部の「未返信」が1増える |
| 2 | **「返信済みにする」を押す** | その行が未返信の一覧から消え、「未返信」の数が1減る。**もう一度押せば未返信に戻せる**（押し間違いを取り消せる） |
| 3 | **探す（検索・絞り込み）** | 名前かメモの文字で検索。未返信／返信済み／全部の切り替え。「先週LINEで来たあの人」を数秒で出す |

> 一覧の行からの **編集・削除** は、テンプレートに既にある補助操作としてそのまま残す（入力ミスの直し用）。新しく作り込むのは上の3つだけ。

## 6. やらないこと

（`CLAUDE.md` 3章＋今回の範囲外）

1. **LINE・電話・HPフォームとの自動連携をしない。** 問い合わせは教室長が手で1件登録する
2. **保護者側の画面を作らない。** フォーム受付・自動返信・体験予約ページは無し
3. **入会後の生徒管理・成績・請求を持たない。** 「返信済み」から先は追わない
4. **状態を5段階（未返信／返信済み／体験予定／入会／見送り）にしない。** 今回は「返信したか、していないか」の2つだけ。分けたくなるかは、使ってもらってから決める
5. **ログイン・課金・メール送信・通知を作らない**（第3回で扱う）
6. **複数人での共有・サーバー保存をしない。** この端末の中だけ
7. **新しいライブラリを追加しない。** テンプレートの構成（Next.js＋プレーンCSS）のまま

## 7. 完成条件

- [ ] **画面を開いた最初の状態で、「返信していない人」だけが、問い合わせ日の古い順（＝待たせている順）に上から並んでいる**
- [ ] **新規登録から1件追加して、ブラウザを再読み込みしても、その1件が残っている**
- [ ] **一覧で「返信済みにする」を押すと、その人が未返信の一覧から消え、上部の「未返信」の数字が1減る**

## 8. 保存方法

`localStorage` に1つのキーで保存する。キー名: **`inquiry-data`**（表示名は `inquiry-appname`）

- 読み書きは **`useEffect` の中だけ**で行う（`useEffect` の外で読むとビルドが落ちるため）
- 読み込みが終わる前に保存を走らせない（`loaded` フラグで止める）
- ※ 端末ごとの保存です。複数人での共有は第3回で扱います
- ※ 保護者の氏名を扱うため、**データは外部に一切送らない**（`docs/01_customer.md` ③の判断どおり）

## 9. ダミーデータ

初回表示で寂しくないよう、サンプルを3件入れる。**実在の人名・連絡先は使わない**（すべて「見本：」で始める）。

| 保護者名 | 流入元 | 問い合わせ日 | メモ | 返信済みか |
|---|---|---|---|---|
| 見本：Aさん（中2） | LINE | 5日前 | 週2希望・英語と数学 | いいえ |
| 見本：Bさん（小5） | 電話 | 2日前 | 18時以降に折り返し希望 | いいえ |
| 見本：Cさん（高1） | HP | 6日前 | 体験の日程を案内済み | はい |

> 「5日前・2日前」は**開いた日から数えた日付**にする。いつ開いても「3日以上待たせている：1件」が成立し、完成条件の1つ目をその場で確認できるため。
