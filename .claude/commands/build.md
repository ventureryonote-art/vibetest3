`docs/03_spec.md` の要件定義書にそって、**触ると動くツール**を実装してください。

**実装の前に `DESIGN.md` を必ず読んでください。**特に **0章（これはアプリ画面であってLPではない）** が最重要です。

### この2つを破ったら、やり直しです

| ⛔ | 内容 |
|---|---|
| **LPを作らない** | キャッチコピー・課題の説明セクション・「無料で始める」等のCTA・営業文は作らない |
| **`docs/` の中身を画面に出さない** | 「やらないこと」「🔮の仮説」「出口の3点」「競合」は社内向け。画面に出したら間違い |

### ⚠ ゼロから作らない。既にあるものを「作り替える」

`app/page.tsx` には、**動く業務アプリが既に入っています。**
左メニュー・一覧・検索・絞り込み・新規登録・編集・削除・設定が、すべて実装済みです。

**あなたの仕事は、これを題材に合わせて作り替えることです。**

| 変えるもの | 変えないもの |
|---|---|
| `Record` 型の**項目名**（name / category / note / date → 題材の言葉に） | **画面の骨格**（`.shell` `.side` `.topbar` `.content`） |
| `CATEGORIES` の中身 | **3画面の構成**（一覧 / 新規登録 / 設定） |
| ラベル・見出し・プレースホルダ・空状態の文言 | 検索・絞り込み・編集・削除・永続化の**仕組み** |
| `SAMPLE`（見本データ3件） | `localStorage` の読み書きの形 |
| 統計（`.stats`）に出す数字の意味 | CSSクラス（**新しいクラスを作らない**） |

### 必ず残す機能（削らない）

- **左メニュー**（一覧／新規登録／設定）と、未対応件数のバッジ
- **新規登録フォーム** — 受講者がその場でデータを入れて試せることが最重要
- **検索**と**絞り込み**（未対応／対応済／全部）
- **編集・削除・状態の切り替え**
- **設定画面**（表示名の変更／見本データの入れ直し／全消去）
- **0件のときの `.empty`**
- `localStorage` への保存（リロードしても消えない）

### 項目を増やしたいとき

`Record` 型に項目を足し、フォームに入力欄を1つ増やし、`.row-sub` か `.badge` で表示します。
**5項目を超えないでください。**入力が面倒になると、その場で試してもらえません。

## 作るもの

`app/page.tsx` を、**1種類のデータの管理ツール**に作り替えます。
メディア・マッチング・決済・ログイン・お客さん側からの入力は作りません
（要件定義書にそれが入っていたら、**管理の部分だけ**に絞って、絞った理由を1行伝える）。

## 技術の制約（必ず守る）

| | |
|---|---|
| ファイル | **`app/page.tsx` の1枚だけ**で完結させる |
| 状態管理 | React の `useState`。ファイル先頭に `"use client"` を書く |
| 保存 | **`localStorage`**。`useEffect` で読み書きする |
| スタイル | `app/globals.css` の**既存クラス**を組み合わせる。直値の色・新しいクラスを書かない |
| ライブラリ | **追加しない。** Next.js と React だけで作る |
| 画面 | 左メニューの**3画面（一覧／新規登録／設定）**。ルーティングは増やさない |

### localStorage の実装で必ず守ること

サーバー側で `localStorage` を触るとビルドが落ちます。**必ずこの形にしてください。**

```tsx
"use client";
import { useState, useEffect } from "react";

const KEY = "xxx-data";

export default function Home() {
  const [items, setItems] = useState<Item[]>([]);
  const [loaded, setLoaded] = useState(false);

  // 読み込みは必ず useEffect の中で
  useEffect(() => {
    try {
      const raw = localStorage.getItem(KEY);
      setItems(raw ? JSON.parse(raw) : INITIAL);
    } catch {
      setItems(INITIAL);
    }
    setLoaded(true);
  }, []);

  // 保存も useEffect。読み込み完了前に走らせない
  useEffect(() => {
    if (!loaded) return;
    localStorage.setItem(KEY, JSON.stringify(items));
  }, [items, loaded]);
  ...
}
```

## 進め方

1. 実装の前に、**何をどう作るつもりか3行以内**で伝える
2. **一度に全部作る。**このコマンドだけは、動くところまで一気に書いてよい
3. 実装後、**ビルドが通るか必ず確認する**（`npm run build` 相当）
4. 要件定義書の「7. 完成条件」を1つずつ照らして、満たしているか自己チェックする

## やってはいけないこと

- 要件定義書の「6. やらないこと」に書かれた機能を足す
- 新しいライブラリを追加する
- `localStorage` を `useEffect` の外で読む（**ビルドが落ちます**）
- `DESIGN.md` の「やらないこと」に当てはまる見た目を作る
  （紫グラデ／中央揃え巨大ヒーロー／同じカード3〜6枚／絵文字アイコン／カード左端の色付き縦線 など）
- **LPを作る**（キャッチコピー・課題の説明・営業文・問い合わせCTA）
- **`docs/` の内容を画面に出す**（特に「やらないこと」の一覧）
- 実在の人名・連絡先をダミーデータに使う
